# GitHub 上传范围

本项目采用“可复现的代码与样例公开，个人运行数据留在本机”的发布方式。

| 内容 | 是否上传 | 原因 |
| --- | --- | --- |
| `app/`、`main.py`、启停脚本 | 是 | 应用源码与入口 |
| `requirements.txt`、`tests/` | 是 | 运行依赖、隔离测试、固定合成评估样例 |
| `compose.neo4j.yml` | 是 | 读取环境变量的图谱配置，不包含真实密码 |
| `.env.example`、`langfuse/.env.example` | 是 | 使用占位符的配置说明 |
| 根目录 `README.md`、`Readme/`、公开 `docs/` 文档 | 是 | 首页入口、完整双语说明、架构、验证记录与合成界面截图 |
| 前端第三方组件、`docs/third-party/` | 是 | 浏览器运行所需资源及其许可署名 |
| `.env` 及其他私有环境文件 | 否 | 模型密钥、数据库密码、观测服务凭据 |
| `data/`、`upload_files/` 的实际内容 | 否 | 个人知识库、会话、上传原件；只保留 `.gitkeep` |
| `temp/`、`.runtime/`、`.local-backups/` | 否 | 日志、进程信息、备份与本地验收产物 |
| 虚拟环境、`node_modules/`、模型缓存 | 否 | 机器相关或可重新安装的大体积依赖 |
| `docs/项目面试与演示指南.md` | 否 | 本地面试准备资料，停止 Git 跟踪并通过忽略规则排除 |

完整项目说明位于 `Readme/README.md` 和 `Readme/README.en.md`。根目录 `README.md` 仅保留 GitHub 首页入口与导航。

## 发布检查

1. 确认 `git status --short`，明确每个拟提交文件。
2. 核对忽略规则；新增环境文件不能仅依赖文件名习惯。
3. 检查工作树、暂存区和将要推送的历史，避免把密钥或运行数据写入提交。
4. 执行 `tests/README.md` 中的隔离回归；真实模型评估另行执行。
5. 核对中英文 README 的语言切换、目录锚点、相对链接与截图。
6. 保留 `docs/third-party/` 中的 Apache 2.0 许可证、上游 NOTICE，以及前端第三方组件许可；模型条款单独适用。

本次准备过程的文件清单、脱敏扫描结果、测试日志及修改前备份保存在本机 `temp/github-publish/`，不进入公开仓库。发布时保留既有 Git 历史，不重写历史或上传本地备份分支。

2026-11-03 本机发布验证：60 项 Python 回归测试通过；Markdown、安全过滤、引用、原文定位、图谱交互、后台任务五组 Node DOM 检查通过。这些验证不调用外部生成模型，不证明模型回答准确率。
